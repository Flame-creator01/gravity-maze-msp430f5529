# 存档系统说明（信息 Flash）

工程把“断电保存进度”放在 MSP430F5529 的信息 Flash 中：每关最佳用时/步数与解锁关卡在重新上电后自动恢复。本文说明数据结构、双备份策略、擦除方式与风险。

## 1. 存什么

`source/drivers/save.h` 中的 `SaveData`：

```c
typedef struct {
    uint8_t  unlocked;                    /* 已解锁关卡数，1..6 */
    uint16_t best_steps[MAZE_LEVEL_COUNT];/* 每关最佳步数，0=未通关 */
    uint32_t best_ms[MAZE_LEVEL_COUNT];   /* 每关最佳用时，0=未通关 */
} SaveData;
```

- 通关时 `Save_ApplyResult()` 比较并更新纪录，返回“是否刷新最佳”与“是否解锁新关”。
- 有变化才写 Flash，避免每次通关都擦写。

## 2. 存在哪里

MSP430F5529 信息 Flash 共 4 段，每段 128 字节：

| 段 | 地址 | 用途 |
|---|---|---|
| INFO A | 0x1980 | **出厂 TLV/校准数据，禁止擦写** |
| INFO B | 0x1900 | 灵敏度参数（TUNE）记录 |
| INFO C | 0x1880 | 进度存档槽 1 |
| INFO D | 0x1800 | 进度存档槽 0 |

本工程只使用 INFO B/C/D。INFO B 存 TUNE 参数，INFO C/D 存关卡进度，互不影响；每个槽用前几十字节，其余保持 0xFF。链接脚本中的 `.infoB/.infoC/.infoD` 段为空，程序不向其中放置代码或常量，运行时直接按地址访问。

## 3. 记录格式

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 2 | 魔数 `0x5341` |
| 2 | 2 | 序号（每次保存 +1，回绕后按有符号差比较新旧） |
| 4 | 1 | 版本号（当前 1） |
| 5 | 1 | 已解锁关卡数 |
| 6 | 12 | 6 关最佳步数（每关 2 字节） |
| 18 | 24 | 6 关最佳用时（每关 4 字节，ms） |
| 42 | 2 | 校验和（初值 0xA5C3 + 前 42 字节累加） |
| 44 | — | 槽内剩余字节保持 0xFF |

记录 44 字节 ≤ 64 字节槽大小，`save.c` 用 `#error` 在编译期检查是否超出。

### 灵敏度参数记录（INFO B）

TUNE 调试台把 7 个参数存到 save-port slot 2（INFO B），单份记录：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 2 | 魔数 `0x5455` |
| 2 | 1 | 版本（当前 2） |
| 3 | 1 | 保留 |
| 4 | 14 | 7 个 uint16：触发、释放、轴余量、慢速、快速、满速倾角、滤波权重 |
| 18 | 2 | 校验和（初值 0x3C5A + 前 18 字节） |

记录 20 字节。上电时 `Tuning_Load()` 校验失败就回退到 `app_config.h` 默认值；TUNE 里长按 S2 才写入。进度（INFO C/D）与调参（INFO B）完全独立，保存其中一边不会破坏另一边。

## 4. 双备份写入流程

1. `Save_Load()`：读两个槽，校验魔数、版本、校验和；两个都有效时取序号较新的一个（用 `(int16_t)(a-b) > 0` 处理序号回绕），否则取唯一有效的槽，都无效则返回默认值（未解锁、无纪录）。
2. `Save_Store()`：
   - 选**另一个**槽（不覆盖当前有效记录）；
   - 擦除该段 → 写 44 字节 → 成功后更新内存中的“当前槽/序号”；
   - 任一步失败立即返回 0，旧槽仍是有效记录，下次读取会回退到旧进度。
3. 这样即使在擦除或写入过程中掉电，最坏只丢最近一次保存，不会两条记录同时损坏。

## 5. Flash 操作细节

`source/drivers/save_port.c` 按 MSP430F5xx 用户指南（SLAU208）与 TI `HAL_FLASH.c` 的方式操作：

- **MSP430F5529 的 Flash 控制器没有 FCTL2**：TI 器件头文件中该寄存器被注释掉，SLAU208 也写明 “FCTL2 ... currently not implemented”。Flash 时序由控制器内部产生，不需要像 MSP430F1xx/2xx 那样配置分频。
- **写/擦 INFO 前要解锁三处**：清 `FCTL3.LOCK`、清 `FCTL4.LOCKINFO`，并**翻转 `FCTL3.LOCKA` 为 0**。`LOCKA` 复位值为 1，而 LOCKA=1 时**所有信息段都不能被段擦除**（不只是 INFO A）。操作完成后把 LOCKA 恢复为 1、LOCKINFO 置 1、LOCK 置 1。
- 进入擦/写前先等待 `BUSY = 0`；所有 BUSY 等待都有上限，Flash 异常时返回失败而不是卡死。
- 擦除：解锁（LOCK/LOCKINFO/LOCKA）→ `FCTL1 = FWKEY | ERASE` → 向段首写 0 触发擦除 → 等 BUSY 清零 → 恢复保护（LOCKA=1、LOCKINFO=1、LOCK=1）。
- 写入：解锁 → `FCTL1 = FWKEY | WRT` → 逐字写入并等待 BUSY → 恢复保护。
- 擦/写全程关闭总中断（保存并恢复 GIE）。
- 写 Flash 期间 CPU 从主 Flash 取指会被控制器暂停，单次保存约数毫秒到数十毫秒；这期间 5ms 按键扫描中断会延迟，系统毫秒计数也可能少计同等时长。保存发生在通关页（计时已冻结），对成绩与操作无影响；若在这几十毫秒内按键，可能丢失一次按键事件。

## 6. 失败与恢复

| 情况 | 表现 | 影响 |
|---|---|---|
| 擦除/写入返回失败 | `Save_Store()` 返回 0，`g_debug.save_ok=0` | 本次上电内不保存，游戏继续 |
| 保存中掉电 | 新槽校验失败，回退到旧槽 | 丢最近一次保存 |
| 两个槽都损坏 | `Save_Load()` 返回 0，使用默认值 | 进度清零，重新从第 1 关开始 |
| 调试器擦除信息内存 | 两个槽都是 0xFF | 进度清零，属正常现象 |

**清除进度**：在 CCS 调试配置里选择擦除信息内存（Erase main and information memory），或用调试器擦除 INFO C/D。**不要擦除 INFO A**，那里有出厂校准数据。

## 7. 代码位置

| 文件 | 作用 |
|---|---|
| `source/drivers/save.h/.c` | 记录打包/校验、双槽选择、应用通关结果（与硬件无关，可主机测试） |
| `source/drivers/save_port.h/.c` | INFO B/C/D 的擦除、按字写入、读取（板级实现） |
| `source/input/tuning.h/.c` | TUNE 参数、默认值/范围、步进曲线、INFO B 读写 |
| `tests/save_port_stub.c` | 主机测试用的内存模型（含擦除失败注入） |
| `source/app/app.c` | `App_Init` 载入进度与调参；通关时更新进度；TUNE 状态处理 |
| `include/app_config.h` | 默认灵敏度参数、`GAME_LEVEL_LOCK` 等编译期默认值 |

## 8. 验证边界

主机测试覆盖：进度默认值、双槽存储/读取、校验和损坏回退、通关结果合并（最佳用时/步数/解锁）、擦除失败不崩溃；TUNE 参数默认值/范围/曲线一致性、INFO B 保存与损坏回退、应用级进入/调整/保存流程。F5529 的 Flash 控制器时序与真实擦写过程无法在主机上执行，`save_port.c` 只通过了寄存器桩下的 C89 语法编译，**未在实物上验证** INFO Flash 的实际写入与断电保持；上板后建议通关一关、断电重上电，观察菜单 `PROGRESS` 与 `BEST` 是否保留，并确认 TUNE 参数掉电后仍在。
