# 测试计划

分两部分：已执行的主机验证（结果原文见 [验证记录](validation.md)），以及待上板执行的目标与实物验证。

## 已执行的主机验证

运行 `tools/test_host.ps1`（需要 GCC）：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\test_host.ps1
```

测试直接编译生产代码中的游戏、地图、校准、消抖、绘图和应用状态机，只有硬件访问替换为主机桩。使用 `-std=c89 -Wall -Wextra -Werror -pedantic`。

覆盖地图行宽与可达性、实际游戏沿路径通关、撞墙不计步、通关冻结、暂停/恢复、时间回绕、移动限速、正负偏置、静置、倾斜方向、晃动校准拒绝、侧放拒绝、按键抖动、长按重复抑制、帧缓冲边界、应用状态转换以及传感器失败与超时。

玩法与存档追加覆盖：六关“收集全部能量点后到出口”的状态 BFS 与真实游戏沿路线通关（含每步位置、步数、收集计数、出口开启、通关冻结）、陷阱退回起点与罚时、出口未开时拒绝进入并提示、倾角调速（190/137/90ms）与限速不可绕过、菜单关卡锁定、存档双槽/校验回退/合并最佳成绩/擦除失败不崩溃、TUNE 参数默认/范围/曲线/滤波权重（1～3）、INFO B 保存与损坏回退、应用级“诊断→TUNE→调整→保存→重载”流程、TUNE 画面渲染；`save_port.c` 通过主机寄存器桩的 C89 语法编译。

按键与传感器追加覆盖：直接编译 `key.c`，通过测试专用 `msp430.h` 模拟 5ms 定时扫描（队列回绕/满、50ms 短按、长按单次触发、毫秒回绕）；直接编译生产 SPI 驱动，用寄存器模型模拟 CMA3000/LIS3DH 与超时，并覆盖应用诊断页重初始化成功、失败、恢复。模型未执行物理器件，不可据此判断 Z 轴硬件正常。

## 待执行的目标与实物验证

上板顺序建议：先按 [传感器诊断与 Z 轴排查](sensor_diagnostics.md) 下载固件，记录板面朝上/朝下的寄存器、mg 与原始计数；若无初始化失败记录错误页。之后可在诊断页按 S1 重新初始化，再长按 S2 重进诊断，对比 Z 是否恢复至约 ±56count。若仍仅约 ±9count，保留观测继续定位，不修改倍率。游戏与长时稳定性验证安排在传感器问题解决之后。

| 测试 | 方法 | 目标 |
|---|---|---|
| TI 编译 | CCS5.5 Build Debug | 无 error，核对 warning 和 map |
| 目标资源 | 查看 map、最坏栈占用 | 不超过芯片 Flash/RAM |
| LCD | 初始化、字符、边界格 | 图像完整，方向和对比度正确 |
| 按键 | 显示刷新时连续短按 S2 10 次，每次间隔约 0.3 秒；另测 S1 与长按 | 每次短按对应一次动作，长按无附带短按 |
| 采样 | 观察有效样本计数，必要时测 SPI | 数据有效，目标约 50Hz 采样 |
| 零点 | 平放校准并静置 10s | 无意外移动 |
| 方向 | 四方向缓慢倾斜 | 与游戏方向一致 |
| 响应 | 记录样本与移动事件 | 默认 130mg 起触发、90～190ms 随倾角变化；轻倾可逐格对准，重倾明显加快 |
| 刷新 | 观察画面和传输周期 | 目标 10Hz，不卡死 |
| 暂停 | 暂停后持续倾斜 10s | 时间、位置、步数不变 |
| 故障 | 软件强制失败返回 | 提示故障并停止移动 |
| 玩法 | 第 1 关收集能量点、踩陷阱、未收集完撞出口 | 出口锁定提示、陷阱退回起点并加 3 秒、HUD 计数正确 |
| 调速 | 轻倾与重倾分别走同一段通道 | 重倾明显更快，轻倾可逐格对准 |
| 解锁 | 通关第 1 关后看菜单 | `PROGRESS` 变 2/6，第 2 关可进入，第 3 关仍 `LOCKED` |
| 灵敏度 | 诊断页长按 S2 进 TUNE，转滚轮调大/调小触发、速度与 FILTER 后长按 S2 保存 | 实时倾角/间隔随参数变化；回菜单后手感立即改变；断电重上电参数保留 |
| 滚轮 | 在 TUNE 里正反向转动滚轮 | 参数按格连续增减；方向与手感一致（不一致改 `WHEEL_INVERT`）；静止不误触 |
| 换向/后摇 | 来回左右倾斜、再回中 | 反向与停止及时；FILTER=3/4 更跟手，1/4 更稳但略滞后 |
| 存档 | 通关后断电重新上电 | 重新校准后 `PROGRESS/BEST` 保留；若丢失查信息内存擦除选项 |
| 稳定性 | 连续游戏 30min，多次重开 | 无卡死、越界或异常复位 |

板载传感器不便物理断开，故障测试优先通过受控的软件返回值注入；不要求拆焊或短接传感器。原理图和 HAL 核对只能证明实现有资料依据，不能替代实物验证。
