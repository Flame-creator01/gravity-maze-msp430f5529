# 调试与问题排查记录

按时间倒序记录开发过程中遇到的问题、处理方式与验证结果。表中“结果”一栏区分**主机测试通过**和**实物验证**，两者不能互相替代。

## 灵敏度与手感调校（2026-11-05 ～ 2026-11-06）

### TUNE 改用滚轮调值（2026-11-06）

问题：TUNE 参数用按键增减，调节体验差。核对 TI 参考设计后确认：这颗“wheel”是**模拟拇指轮（电位器）**，P8.0 高电平使能，滑臂接 P6.5/ADC12 通道 A5（`HAL_Wheel.c`），并非正交编码器。

处理：新增 `source/drivers/wheel.c`，ADC12 单通道单次转换，按相对位移每 96 个计数产生一个 tick（`Wheel_Poll` 返回 −6～+6），无需绝对位置校准；应用每 20ms 采样时轮询，非 TUNE 状态丢弃 tick 只更新参考点。TUNE 按键改为：滚轮调值、S1/S2 短按切换参数、长按 S2 保存、长按 S1 不保存返回；`DEFAULT` 项转轮恢复默认。

结果：主机测试用滚轮桩覆盖调值流程，`wheel.c` 通过 ADC 桩语法编译；转向与读数待实物验证。

### 换向与后摇调校（2026-11-05）

问题：换方向响应慢、回中后还有后摇。原因分析：低通滤波权重 1/4（时间常数约 60ms）使反向过零和回中衰减偏慢；释放阈值 80mg 让方向多保持几步；轴切换余量 45mg 偏保守。

处理：滤波权重改为运行时可调（默认 2/4 = 1/2），释放阈值 80→100mg，轴切换余量 45→35mg；TUNE 新增 `FILTER` 项（1/4、2/4、3/4），参数记录版本升到 2（INFO B）。

结果：主机测试按新参数更新并通过，实物手感待确认。

### 灵敏度调试台 TUNE（2026-11-05）

动机：不重新编译就能调手感。新增 TUNE 状态：从诊断页长按 S2 进入，S2 短按切换参数，长按 S2 保存到 INFO B（当时用 S1 短按 +、长按 − 调值，后改为滚轮）。可调 6 个参数（触发/释放阈值、轴余量、慢速/快速间隔、满速倾角，后加 `FILTER` 共 7 个），实时显示滤波后倾角、计算出的每格间隔、方向，以及 0～900mg 倾角条（触发/满速标记与当前倾角）；`DEFAULT` 项可一键恢复默认。

运行时参数集中在 `g_tuning`，运动/游戏直接读取，退出调试台立即生效；`App_Init` 从 INFO B 载入并做范围/曲线一致性钳制。INFO B 与进度 INFO C/D 分离，互不破坏。

主机测试新增：参数默认/范围/曲线、INFO B 保存/损坏回退、应用级进入→调整→保存→重载流程、TUNE 画面渲染；全部通过。**未在实物上验证**按键手感、LCD 倾角条与 INFO B 掉电保持。

### 响应速度调校（2026-11-05）

问题：响应太慢、阈值偏高。原默认要倾到 220mg（≈12.7°）才动、最快速度要 800mg（≈53°），日常倾斜下每格约 240～260ms。

处理：改为更灵敏的默认值——触发 130mg（≈7.5°）、释放 80mg（≈4.5°，后调为 100mg）、轴切换余量 45mg；每格 190ms（≤130mg）线性降到 90ms（≥450mg≈26°）。参数都在 `app_config.h`。

结果：主机调速用例按新参数更新并通过，实物手感待确认。未改校准、收集、陷阱和存档逻辑。

## 构建与驱动问题

### CCS 编译错误 `FCTL2 is undefined`（2026-11-05）

现象：CCS 构建报 `save_port.c: line 37: error: identifier "FCTL2" is undefined`。

根因：核对 MSP430F5529 器件头文件与 SLAU208，**F5xx 的 FCTL2 未实现**（头文件中被注释掉）；写/擦信息存储器必须先清 `FCTL4.LOCKINFO`，并且 **`FCTL3.LOCKA` 复位为 1，LOCKA=1 会禁止所有信息段的段擦除**。

处理：删除 FCTL2 时序配置，改为“清 LOCK → 清 LOCKINFO → 翻转 LOCKA → ERASE/WRT → 恢复保护”的官方序列，并在每次操作前检查 BUSY；主机寄存器桩同步为真实位值、移除 FCTL2 并加入 LOCKA。

结果：主机回归通过，需要在 CCS 中重新构建确认。此修复不改变游戏与存档数据格式。

### 导入提示 meta-data cannot be interpreted（2026-11-05）

处理：对照 TI 原版工程，补回两处 XML 处理指令——`.cproject` 的 `<?fileVersion 4.0.0?>` 与 `.ccsproject` 的 `<?ccsproject version="1.0"?>`。普通 XML 语法检查发现不了这类 CCS/CDT 格式问题。

结果：文件静态检查通过，尚未在 CCS 5.5 中验证导入；恢复步骤见 [CCS 导入与编译](ccs_setup.md)。

### 加速度计幅度排查（2026-11-05）

现象：实物丝印为 SEEED-EXP430F5529 V1.0，TYPE=1。失败页 DX=54、DY=72、DZ=18mg，Z 均值约 +168mg——稳定性检查满足阈值，但 Z 重力分量不足。后续观测：X 侧立约 −1008mg，板面朝上 Z 约 +162mg，朝下 Z 约 −162mg。之前对 X 数值和翻面符号的误读已更正；Z 有响应，幅度偏小，根因未定。

依据：CMA3000-D01 Rev.A.03 四页手册确认 ±2g/400Hz 下 56count/g，18mg/count 近似合理。

处理：新增原始计数/寄存器诊断、CMA3000 复位序列、SPI 结束忙等待及事务间隔；保留校准阈值，不补偿 Z 增益。

结果：生产驱动 SPI 模型、超时注入、应用诊断与重试、原有游戏/按键/校准回归均通过主机测试；尚未在实物上确认读数。不能据主机结果宣布修复硬件。详见 [传感器诊断与 Z 轴排查](sensor_diagnostics.md)。

### 按键改为定时中断扫描（2026-11-05）

现象：LCD 显示 `CALIBRATE` 正常，但 S1 有时响应、有时不响应。旧版本仅在主循环扫描按键，LCD 绘图与整屏传输会延后下一次扫描，存在漏掉短按的可能。

处理：Timer_A0 每 5ms 扫描 S1/S2（显示刷新期间也能扫描），消抖时间由 30ms 改为 20ms，最多暂存 7 个待处理事件由主循环按序取出，满时保留旧事件、丢弃新事件；长按仍约 0.8 秒，释放后不附带短按。

结果：主机模拟驱动测试及既有回归通过，待实物复测。中断的实际执行耗时、调度精度或物理按键接触情况不能由主机测试证明。

### 校准改进：1 秒静置 + 失败原因分类（2026-11-05）

现象：`KEEP STILL` 后样本数增长，但最终显示 SHAKY / NOT FLAT。这说明程序接收了校准事件并持续收到样本，是校准检查未通过，尚不能据此确定是实际晃动、板面倾斜还是传感器读数异常。

处理：旧版在松开 S1 后立即采集样本，按键施力引起的振动可能被计入统计；现在在按键松开后加入 1 秒静置等待，期间读取的加速度不计入校准统计，再正式采集 64 个样本。失败页区分波动、Z/姿态、X/Y 倾斜并显示峰峰差与 Z 均值，不扩大任何阈值。

结果：静置期样本忽略、按键后短时晃动不参与统计、等待期重复短按不重置、长按取消、计数回绕、三类失败原因、失败后重试、正反 Z 重力分量与全量程峰峰差计算等主机测试通过；实物复测待诊断数值。

### 左右方向修正（2026-10-29 ～ 2026-11-05）

实物验证反馈左右移动反向。处理：`MOTION_X_SIGN` 从 1 改为 −1，方向测试输入按新的物理映射调整，保留负偏置、左右/上下和全量程峰峰差覆盖。未新增传感器实测数值，不推断 Z 异常的历史根因。

结果：主机回归通过；左右方向需重新下载后在实物上确认。

### CCS 提示 `last_direction was set but never used`

处理：删除 `game.c` 中未被读取的变量及其赋值，保留基于 `last_move` 的移动限速。

结果：主机回归测试通过。此清理不构成按键故障修复。
